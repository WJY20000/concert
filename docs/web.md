# 网页实测

在 Windows 上安装 Node.js 22 或更高版本和 Chrome，进入仓库目录后执行 `npm ci`。用独立的 Chrome 用户目录开启本机调试端口。

```powershell
& "$env:ProgramFiles\Google\Chrome\Application\chrome.exe" --remote-debugging-address=127.0.0.1 --remote-debugging-port=9222 "--user-data-dir=$env:LOCALAPPDATA\ConcertChrome"
```

在新窗口登录购票账号，保存观演人，进入目标演出详情、选票或确认订单页。只保留一个与配置中购票路径匹配的标签页。保留独立目录，下次启动可沿用登录状态。脚本通过本机 CDP 连接这个窗口。脚本退出后可以继续在原窗口核对订单和手动付款。

## 按演出校准配置

把 `profiles/web.json` 复制到本机配置目录，并修改主配置里当前平台的 `web` 路径。映射示例中的域名、路径和 CSS 要逐页在实际购票界面核对。示例已限定你提供的详情页演出 ID `1102631725191`。订单页路径和多数样式类仍需实测填写。这场演出的预约详情页已用本地归档核对，能读取登录状态、标题、场次和 88 元早鸟档。归档中的「预约抢票」处于禁用状态。开售后的数量控件仍需现场核对，确认页和查单页需按实际页面配置。其他演出要同步修改详情和选票层的查询条件。用 Chrome 开发者工具的元素检查器逐项点选页面上的文字或按钮，确认它的稳定 ID、类名、可访问性属性和所属区域。

- `stages` 声明流程涉及的画面。每个画面的 `origin` 写 HTTPS 源，`path` 写完整路径，变化的单段 ID 可写成 `:id`。`query` 指定固定查询参数，例如演出 ID。`ready` 和 `login` 各匹配一个可见元素，分别表示该画面已经加载和用户已经登录。弹层与底层使用同一路径时，要让它们的 `ready` 条件互斥。例如将详情标记限制为弹层关闭时才匹配。可删除实际流程中没有的画面。
- `blockers` 匹配需要人工完成的登录或验证提示，验证码嵌在 iframe 中时可匹配可见外框。`soldOut` 只匹配当前所选票档或座位的售罄状态。
- `fields` 读取当前的选中结果或订单摘要。`event`、`session`、`tier` 等单值选择器各匹配一个可见元素，`quantity` 宜定位只显示张数的节点。`seats` 和 `attendees` 各匹配已选的各个座位名、观演人姓名，每项一个节点。订单确认页上的完整可选名单不适合作为已选摘要。属性值可用对象读取，例如 `{"selector":"time.order-created","attribute":"datetime"}`。
- `choices` 为场次、票档、座位或实名观演人提供可点击选项。`rows` 定位候选行，`label` 和 `control` 在行内查找精确名称和点击控件。`:scope` 代表行本身。`selected` 必须能在行本身或其后代上匹配已选状态，例如 `input:checked`。确保手动选择、取消选择时页面实际切换了该状态。若座位名存于可访问性标签，可以设置 `"label": ":scope", "labelAttribute": "aria-label"`。Canvas、图片座位图需要平台提供可识别的独立座位控件；也可以手动选好，进入有完整座位摘要的确认页。
- `actions` 用 CSS 和完整按钮文案共同定位。二维码区的「不，立即购票」属于 `enter`，按界面使用真实标点。座位页「确认选座」属于 `next`。确认页的 `submit` 必须仅创建待支付订单。图标控件可以从 `aria-label` 读取名称。相同名称匹配多项时会停下，收窄选择器后重试。
- 提交后 `order` 映射真实订单详情页的 `orderId`、`status`、完整选票信息和观演人。若平台显示本次提交的编号，将其映射到回执的 `submittedOrderId`。详情的 `createdAt` 应提供含时区的 ISO 时间。可选动作 `orders` 打开订单列表，`openOrder` 打开最新订单详情。两者都应是只读导航。由订单列表进入详情后，需要提交回执编号一致或详情创建时间足够新；两种证据都缺失时会报告状态不明，请人工核对。
- 同一适配器可以对接其他提供网页购票的服务。在独立映射文件里为 `additionalOrigins` 填入经核对的 HTTPS 源，如 `["https://tickets.example.org"]`，并给每个画面配置准确的路径、已登录标记和控件。未提供此项时仅接受大麦 HTTPS 域名。跨站支付跳转后的第三方页面由用户操作。

## 第一次使用

先在已登录的浏览器中打开实际页面，用控制台或命令行的检查模式核对当前阶段、可见字段及控件数量。再用演练流程检查座位和观演人选择以及到达确认页的状态。根据主配置给同一场演出设置固定的开售时间和相同购票条件。实测时记录从开售到核实待支付的时间；页面操作耗时会随设备、网络、库存和服务端排队变化。
